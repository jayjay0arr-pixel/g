# Recall Rush (Android app project)

Your HTML app wrapped for Android with Capacitor. All three batches are done: the project builds a debug-signed APK in GitHub Actions on every push.

## What is in here

| Path | What it is |
|---|---|
| `www/index.html` | Your app. Data and progress removed, no Google Fonts / CDN links, Save button replaced by a sync status chip |
| `www/rr-native.js` | The Android layer: first-launch folders, data sync, status chip, back button, PDF/.txt export |
| `scripts/prepare-web.mjs` | Copies fonts + PDF libraries from `node_modules` into `www/` (offline) |
| `scripts/patch-android.mjs` | Run after `cap add android` (safe to repeat; `--check` only verifies): permissions, rotation, keyboard resize, edge-to-edge opt-out, bar colours, icon + splash wiring, targetSdk 35, share paths, fixed debug key |
| `scripts/make-assets.mjs` | Draws the icon and splash (your orange ring) and writes them into `android/.../res`. No dependencies |
| `signing/debug.keystore` | Fixed debug signing key (see "Updating the app" below) |
| `.github/workflows/build-apk.yml` | The cloud build |
| `assets/preview/` | Pictures of the icon and splash, for a look. Not used by the build |
| `tests/` | Optional headless-browser and patch-script checks (see `tests/README.md`). Not needed to build the app |
| `capacitor.config.json` | App id `com.recallrush.app`, name "Recall Rush" |
| `package.json` | Dependencies and scripts |

There is no `android/` folder in the project. It is generated by `npx cap add android` in every build and is kept out of git (`.gitignore`), so everything Android-specific lives in `scripts/patch-android.mjs` and `scripts/make-assets.mjs`.
Fonts (`www/fonts/`) and libraries (`www/lib/`) are also generated (`npm run prepare-web`) and not committed.

## Getting the APK (GitHub Actions)

1. Create a GitHub repository (private is fine) and push this folder to it (the contents of `recall-rush-app/`, so that `package.json` and `.github/` sit at the top of the repo).
2. Open the repository's **Actions** tab. The **Build APK** workflow starts by itself on every push. To start it by hand: Actions > Build APK > **Run workflow**.
3. Wait for the green tick (first run about 6 to 10 minutes, later ones faster).
4. Open the run and scroll to **Artifacts** at the bottom. Download **recall-rush-debug-apk**. It is a zip with one file inside: `recall-rush-debug.apk`. Unzip it (on a phone the Files app can unzip).
5. If the run is red, open the failed step and send me its text. The workflow checks its own work (patch check, target SDK 35, app name, signing key), so the failing step name says where it went wrong.

The workflow does what you would do by hand: `npm install`, `npm run prepare-web`, `npm run android:add` (only when `android/` is missing), `npm run android:patch`, `npx cap sync android`, `npm run android:check`, then Gradle `assembleDebug`. Node 22 and Java 21.

## Installing on your phone

1. Get `recall-rush-debug.apk` onto the phone (download the artifact on the phone, or download on a computer and send it by USB, Drive, Telegram saved messages, etc.).
2. Tap the APK in the Files app (or in the browser's download list).
3. First time only: Android says it can't install apps from this source. Tap **Settings** and switch on **Allow from this source** for the app you opened the APK with (Files, Chrome, ...). Go back and tap the APK again.
4. If Google Play Protect says "App blocked" or "Unknown developer", choose **Install anyway** (or **More details > Install anyway**). It is a debug build that is not from the Play Store.
5. Tap **Install**, then **Open**.

### Updating the app

Every build is signed with the same key (`signing/debug.keystore`), so a newer APK installs straight over the old one and keeps the app's data. If you ever see "App not installed" it means the old copy was signed with a different key (for example one you built before this project had a fixed key); uninstall it once, then install. Your data survives because it is mirrored to `Documents/RecallRush/recall-rush-data.json` (see below). The keystore holds the standard public debug password (`android`); it is not a secret and is not a Play Store key.

### First launch

- The app creates `Documents/RecallRush/` with empty `ESAS`, `MATH` and `EE` folders and a data file `recall-rush-data.json`.
- On Android 10 and older, Android asks to allow access to photos, media and files: tap **Allow**. On newer Android there may be no prompt at all; that is normal.
- The chip in the header shows **Synced to Documents/RecallRush** when the data file is being kept up to date. If it says **Saved in app only**, Documents was not writable on that phone; the app still works and keeps your data in its own storage.

### Putting your old data on the phone

Your data is in `recall-rush-my-data.json` (not in this project). The app reads `Documents/RecallRush/recall-rush-data.json` when it starts, and it treats whichever copy is newer as the winner, so the order matters:

**Best (before the first launch):**
1. In the Files app create the folder `Documents/RecallRush`.
2. **Copy** (do not move, keep your original safe) `recall-rush-my-data.json` into it and rename the copy to `recall-rush-data.json`.
3. Install and open Recall Rush.

**If you already opened the app once** (it has created its own empty data file):
1. Close the app. Settings > Apps > Recall Rush > Storage > **Clear data** (this clears only the app's private copy; the Documents file stays).
2. In `Documents/RecallRush/` replace `recall-rush-data.json` with a copy of `recall-rush-my-data.json` (same name).
3. Open the app.

**Confirm it loaded:** Formula bank shows your topics and folders, the Progress page shows your XP and streak, and the chip says **Synced**. In the Files app the data file should not have shrunk to a few hundred bytes.

If nothing shows up, do not open and close the app repeatedly; send me what the chip says and which Android version the phone runs.

## Exporting (Print / PDF / .txt)

Android's WebView cannot download files or open a print dialog, so on the phone these buttons work differently (on a laptop browser nothing changed):

- **Review > Save PDF**, **List > Save as PDF**, **List > Save as .txt**: the file is written to `Documents/RecallRush/Exports/`, a message shows the path, and Android's share sheet opens so you can open it, send it, or save it to Drive.
- **Review > Print**, **List > Print list**: make the same PDF and open the share sheet. Choose **Print** there (most phones have it) or open the PDF in a viewer and print from there.
- **List > Copy as text**: copies with the phone's own clipboard and shows "List copied."
- If Documents cannot be written, the file goes to the app's cache instead and the message says so. Share it from the sheet right away to keep it.

## What the app does on your phone

1. First launch creates `Documents/RecallRush/` with empty `ESAS/`, `MATH/`, `EE/` folders.
2. Every change (formulas, folders, progress) is mirrored to `Documents/RecallRush/recall-rush-data.json`.
3. On launch the app reads that file back. Newer data wins, so reinstalling the app does not lose anything.
4. If Documents cannot be written (some phones), it keeps the data in the app's private storage and the chip says "Saved in app only".
5. Back button: closes the open menu or picker, goes up a folder, leaves a quiz (asks first), returns to the home screen, and exits on a double press.

## Portrait, keyboard, rotation

**Portrait layout.** On a phone held upright (narrow portrait), the header becomes three rows (logo / title / sync chip / menu, then the tabs, then Round / Score / Combo and the practice scope), and the play screen fits one screen with no scrolling: formula name, calculator display, level + symbol chips, Check/Hint/Clear/I forgot/End, the function keys and the number pad. Key rows share whatever height is left, so taller phones get bigger keys. Notes:
- "Greek letters" now swaps in for the function keys instead of growing the page (tap it again to go back).
- On the units/answer step the keypad is not used, so it is hidden and the unit fields get the room.
- If a screen is genuinely too short (very small phones, or the phone keyboard is open), the page scrolls instead of clipping anything.
- Landscape and laptop layouts are unchanged (checked pixel-for-pixel against Batch 1).

**Keyboard control (touch screens only).** The on-screen keypad is the input, so every typing/answer field on the play screen (`#kb`, `#ty`, unit fields) has `inputmode="none"`, plus `readonly` as a second lock for keyboards that ignore `inputmode`. The **⌨** button in the top-right of the calculator display switches the phone keyboard on and off; while it is on, tapping keypad keys does not close the keyboard. The Formula bank, Review "Find", List "Find" and edit boxes are untouched and use the normal keyboard. On a laptop nothing changes (the ⌨ button is hidden).
- Hard level needs the phone keyboard (the on-screen keypad has no Latin letters), and so do the unit fields; tap ⌨ for those. On the units step the ⌨ button pulses to remind you.

**Rotation / keyboard / bars (`scripts/patch-android.mjs`).**
- `android:screenOrientation="user"`: follows the phone's auto-rotate. Auto-rotate off = stays as the phone is locked (normally portrait); on = turns to landscape when you turn the phone.
- `configChanges` includes orientation/screen size so rotating does not restart the app.
- `android:windowSoftInputMode="adjustResize"` so the page shrinks when the keyboard opens.
- `android:windowOptOutEdgeToEdgeEnforcement=true` in the app themes. Capacitor 7 builds for Android 15, which forces apps to draw under the status/navigation bars, and in that mode `adjustResize` alone does not shrink the page for the keyboard. The opt-out restores the classic behaviour. Android ignores it for apps targeting Android 16 (API 36) or higher; Capacitor 7 targets 35, and the script warns if that ever changes.

## Known limits

- The phone-only parts were never run on a real phone. The Android build itself was never run in the sandbox (no Android SDK, and npm/GitHub were not reachable there), so `cap add android` and Gradle have not been tried on this exact project. The workflow's check steps are there to fail loudly instead of producing a half-patched APK.
- Android 11 and newer restrict apps from reading files that other apps put in Documents. If the app cannot read the data file you copied in, it may start empty (the chip can still say Synced, because the app can write its own file). Keep your original `recall-rush-my-data.json` safe, and tell me if this happens: the fix is an "Import data file" button in the app, which I have not added because you asked to copy the file yourself.
- "Open" after an export goes through Android's share sheet; there is no direct "open in PDF viewer" button.
